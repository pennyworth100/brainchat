# Write-capacity responses (private 3.0.33 candidate)

The opt-in message admission fixture raises PostgreSQL SQLSTATE `53100` when
its append-only row/UTF8-envelope budget is full. This is a **logical budget**,
not disk, WAL, inode, transient allocation or sustainable load authority.
No admission migration, live budget, deployed role/pool or public resume is
activated by this change. Production remains unchanged.

## Public producer contract

- Socket text/image: error ACK `WRITE_CAPACITY_EXHAUSTED`, original operation key,
  `outcome: unknown`, `autoRetry: false`; no success receipt or success event.
- Keyed/unkeyed agent HTTP: 503 with the same capacity/unknown/no-auto-retry
  envelope; no `Retry-After`. An append-only budget does not replenish with time.
- Legacy multipart: 503 preserving `UPLOAD_OUTCOME_UNKNOWN` compatibility, with
  `reason: WRITE_CAPACITY_EXHAUSTED`. Preserve bytes and release only settled
  ownership. The existing browser uploader never retries this envelope.
- Existing durable keyed receipts remain readable at capacity without charging
  again. This is not permission to replay an uncertain unkeyed request or replay
  a socket operation after a new normal-join session.
- Inspect only at most four driver/wrapper causes, with cycle detection. Never
  classify error-message text or expose database error/SQL details to clients.

A capacity signal does not establish whether any previous attempt committed.
These replies deliberately do **not** assert rollback. Other unknown failures
keep their existing handling. Private strict-file composition is unchanged and
is not covered by the public legacy multipart capacity proof.

## Actual integration proof

After `npm run build`, run the disposable fixture with `PG_BIN` configured:
`python3 scripts/qa-public-session-fixture.py --publication`.
Do not rebuild `.next` concurrently with this production-server fixture.

The fixture installs the budget CLOSED at exact existing occupancy, exercises
real SQL53100 for socket text/image, keyed/unkeyed agent and multipart, checks
unchanged message/journal/receipt/budget state, no sender/peer success events,
preserved exact upload bytes, and same-key socket/agent receipt reads at capacity.
It also retains previous producer fault/rollback tests and verifies journal
recovery after immediate stop/restart of its owned PostgreSQL, then stops it.

Remaining activation gates: defensible admission/load policy; separate deployed
runtime/maintenance roles and pools; public rendered resume/reload/file-byte
acceptance; physical provider contract; current paired backup at a proven old
writer fence; exact new-image audit/deploy/rollback. Existing production GO
does not waive these technical gates.
