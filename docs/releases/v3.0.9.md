# Dimle 3.0.9 — quiet room liveness checks

The visible-room 15-second timer now checks authenticated socket membership
without fetching the last 100 messages or moving a healthy editor through
`syncing`. It shares overlapping requests. A timeout, invalid response or
membership rejection triggers the existing bounded reconnect/rejoin and full
history synchronization. A late response cannot restart a replacement socket.

Foreground/pageshow/online/focus recovery, uploads and pre-send synchronization
still fetch full history. This is a transport/membership liveness check, **not**
proof of database availability, durable resume, history completeness or message
delivery. Existing Socket.IO ordering/reconnection behavior is unchanged.

The server accepts `sync-room { roomId, probeOnly: true }` only for the currently
joined room, adapter membership and online-user entry. The response is only
`{ ok: true }`; there is no history query or credential in the response.
Malformed and wrong-room requests fail closed. Older clients retain full sync;
new clients tolerate an older server's snapshot ACK during a rolling upgrade.

## Verification and release boundary

Local Node 24: 38 unit/regression tests (including six real Socket.IO quiet-health
cases), five plugin tests, TypeScript and production build pass; production
dependency audit reports zero vulnerabilities. The existing PostgreSQL integration
harness now also rejects outsider, malformed and wrong-room probes and checks the
minimal authorized response. CI must pass before integration.

This patch implements only the quiet-probe slice of BRA-11. Server-verified
resume tokens, generation/CAS, revocation, cursor-gap UX and physical browser
acceptance remain open. It does not implement the full safe-resume contract.

No DB migration, new dependency, listener v7 change or live test is included.
Keep product staging 3.0.5 and production 3.0.3 unchanged. Source integration is
not staging permission, a physical-test brief or production approval.
