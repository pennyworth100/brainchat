# Actual public producers and private journal

Run `python3 scripts/qa-public-session-fixture.py --publication` with `PG_BIN`
and an existing production build. The fixture owns a disposable loopback
PostgreSQL cluster, upload directory and actual server.ts process. It explicitly
replaces inherited agent keys with a random, fixture-only key (never logged).

Only this opt-in fixture installs the private publication SQL. There is no
startup migration registration, public resume activation or live database change.

The existing authenticated socket/HTTP suite now runs with the trigger installed:
actual ResumeMessageWriter, ResumeImageWriter, legacy upload transaction,
text/image replay, authorization rejection and blocked INSERT/disconnect rollback.
Additional HTTP calls exercise unkeyed saveMessage and keyed saveAgentMessage,
same-key replay and payload conflict. A database trigger rejects both actual
post-commit activity updates; a nontransactional sequence proves both faults ran.
The expected HTTP result is 200: RoomActivityWriter absorbs the activity failure,
so it cannot turn the already committed message into a retry signal. Both
messages retain exactly one matching journal row.

Final checks prove every committed message has a matching same-room journal row,
there are no orphan journal rows, all three message types were exercised, and
conflicting/rolled-back messages were not persisted.

After the application settles and exits, the wrapper immediately stops and
restarts its owned database. A fresh Node process/pg connection verifies the nonempty exact
same-room message/journal correspondence after recovery. This does not claim an
application crash, loss of a publication ACK or production paired-backup proof.

This is not rendered delivery, actual fanout-failure injection, public resume,
strict-file endpoint activation, reload durability or provider capacity evidence.
The strict ResumeFileWriter remains covered separately by the private writer
composition fixture. Role/UPDATE/DELETE policy, retention/capacity, full browser
activation and release backup/audit gates remain open.
