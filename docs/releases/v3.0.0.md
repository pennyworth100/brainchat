# Dimle 3.0.0

Release candidate focused on functional stability and security after staging acceptance.

## Verified

- Next.js production build succeeds.
- Security unit tests pass (5/5).
- Production dependency audit reports no known vulnerabilities.
- Room identifiers are cryptographically random; legacy four-digit rooms remain supported.
- Room passwords use Argon2id hashes and room creation uses one-time claim tokens.
- Room creation and join attempts are rate limited through PostgreSQL.

## Security changes

- Uploads require an active Socket.IO membership in the target room.
- Uploads have a separate per-client rate limit and a 100 MB size cap.
- Uploaded files are served as downloads with same-origin resource policy.
- Message, username, metadata, JSON-body, and inline-image sizes are bounded.
- Active inline images are restricted to PNG, JPEG, GIF, and WebP data URLs.
- Added CSP, referrer, permissions, anti-framing, MIME-sniffing, and HSTS headers.
- Removed the Express technology disclosure header.

## Version policy

Subsequent corrections increment the patch number: `3.0.1`, `3.0.2`, and so on.
