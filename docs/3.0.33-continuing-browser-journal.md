# 3.0.33 — private continuing browser journal

After an exact full/empty snapshot confirmation, the controller seeds a bounded
memory-only journal. `receivePublication(physical, ticket, envelope)` requires the
same live lease, physical connection, generation and request. Foreign tickets
are rejected before touching the active projection. Disconnect/rejoin cancels it.

The server's `reconcileBrowserPublication` normalizes committed text/image/file
rows and uses the existing authorized journal claim/ACK path. The caller starts
polling only after snapshot confirmation and owns cadence/lifetime. Existing
per-socket/global flight bounds, SQL authorization, lease and physical fences
remain in force. No public handler or timer is installed by this change.

## Retention and ACK semantics

- Maximum 16 rows per incoming batch; retain at most 256 unique rows and 1 MiB
  of normalized UTF-8 JSON, including the seed. No eviction or truncation.
- Exact duplicate IDs/content are retained once but ACKed on every valid retry,
  including a new delivery lease. Conflicting content for an ID fails closed.
- IDs order the displayed projection, not commits. A later lower-ID commit is
  merged even after higher IDs were included in the confirmed snapshot.
- The browser ACK covers exactly the incoming batch, never all retained rows.
  It proves in-memory retention only. Server SQL settlement happens afterwards.
- A malformed envelope, conflict or capacity breach blocks this controller.
  Existing operation ownership/payload handling is not settled by journal rows.

## Evidence and remaining gates

The owned PostgreSQL/Socket.IO fixture allocates a lower ID in an open transaction,
confirms a snapshot containing a later higher ID, then commits the lower ID.
It delivers that row plus later text/image/file metadata to the actual controller.
It deliberately drops the first batch ACK, expires only the fixture's lease,
redelivers under a new deliveryTry, and verifies identical retained IDs and
durable server ACK settlement. The controller stays SYNCING throughout.

Unit regressions cover duplicate/conflict handling, count/byte exhaustion, strict
envelopes, media normalization, confirmation ordering, stale physical/ticket,
lease expiry and disconnect/resume fencing.

This is NOT browser READY, rendered UI acceptance, automatic reconnect, reload
durability or a public file-byte proof. A retained projection is not a sustainable
retention policy. Public activation still needs coherent polling/READY ownership,
authenticated rendered acceptance, pending payload/reload handling, all actual
producers, migration/role/tombstone review and recovery/storage capacity gates.
