# Private request-bound snapshot confirmation (3.0.33)

`createBrowserPublicationExchange` composes the normalized full-cut publisher
with durable `acknowledgeSnapshot`. It is not registered on the public server
and does not grant browser READY.

## Retained authority

- The server captures room, session, generation and request ID from an exact
  physical owner/membership. Copied owners/bindings and foreign sockets fail.
- One exchange token per physical socket; creating a successor permanently
  retires the predecessor, including its pending read or settlement.
- The exchange owns the captured SQL cut and exact ordered ID set. An ACK must
  match the request identity, delivery attempt and complete set, even when empty.
- A four-second monotonic exchange deadline is conservatively shorter than the
  five-second SQL cut lease. The SQL gate still checks durable authority/lease.
- Settlement shares history-sync per-socket and global in-flight limits.
  Disconnect/timeout fences output but does not release unresolved SQL work.
- Confirmation is handed off only after durable settlement returns and current
  physical membership, request token and deadline are rechecked.
- Lost confirmation can retry this same still-live exchange; every retry checks
  SQL again. No cached success authorizes a stale connection.
- Return `true` means synchronous confirmation handoff, NOT network delivery,
  persistent browser receipt or permission to skip journal reconciliation.

## Evidence and limits

Unit regressions cover full/empty cuts, immutable request/ACK retention, wrong
request/authority, forged sets, concurrent settlement, denied settlement, lost
confirmation, superseded reads and disconnect/expiry/deadline/supersession during
pending settlement.

The owned PostgreSQL subscriber fixture additionally sends real normalized cuts
to a Socket.IO client, settles SQL, deliberately loses the first confirmation,
retries and verifies receipt of the exact request-bound confirmation. It checks
full and empty cuts and that a later committed message remains claimable.

The existing durable full/empty cut recovery fixture remains in the same
immediate-stop/restart suite. Transport confirmation itself is not persisted in
the browser. Browser READY, bounded retained deduplication, continuing journal
reconciliation, reconnect/reload and public activation remain separate gates.
No migration registration, dependency change, integration or deployment.
