# Dimle 3.0.6 — private-message delivery confirmation

Fixes #12: a half-open socket could previously report a private message sent
without any live recipient receiving it. The server now waits up to 5 seconds
for the receiving browser to acknowledge receipt before reporting success.
The composer waits up to 7 seconds and retains its text on failure or uncertain
delivery. There are no automatic retries: loss of an acknowledgement does not
prove loss of the message, so users are asked to check before retrying.

Multiple room sessions sharing a nickname are rejected explicitly, without
broadcasting a DM, selecting an arbitrary namesake, or evicting a live session.
Normal disconnect/heartbeat cleanup restores single-recipient routing.
This is not an identity redesign, persistent DM storage, or read receipts.

Older receiver tabs do not acknowledge DMs: they may receive a message but the
sender sees an unconfirmed result until the receiver refreshes. Older sender
tabs still receive private-message-sent/error events, but cannot retain drafts
with the new UI behavior until refreshed. Deploy/rollback requires this caveat.

No database changes or new dependencies. Product 3.0.6 and listener package v5
are independent. Production deployment requires fresh explicit Max approval;
staging listener restart, candy986 sends and physical BRA-11 remain on HOLD.
