# Dimle 3.0.3

Status: staging candidate. Production remains on the currently accepted release
until staging verification and Max's explicit production acceptance.

## Readable room names

- New rooms use a short common English noun followed by three digits, for example
  `apple482` or `river037`.
- The nouns are curated for simple spelling and phone dictation; no runtime word
  service or additional production dependency is required.
- Join input explains the format and accepts uppercase letters by normalizing new
  readable names to lowercase.
- Existing 4-digit and 16-character room IDs remain valid, so active and saved
  links keep working.
- Server API, upload and Socket.IO join boundaries normalize readable names before
  database or presence lookups.

## Security note

Readable room names are locators, not secrets. Rooms that require access control
must use a password. Existing join and room-creation rate limits remain in place.

## Included from 3.0.2

- Mobile reconnect, room resynchronization and reliable upload persistence.
- CI-backed unit, type, build and PostgreSQL/Socket.IO integration checks.
