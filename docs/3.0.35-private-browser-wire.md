# Private negotiated recovery candidate (3.0.35)

This is a **text-only private acceptance surface**, not the public room migration
or a production release. `server.ts` defaults to protocol disabled and returns
404 for `/candidate-recovery`. The isolated three-role `candidate-server.ts`
explicitly enables it, with publication tables required. No environment fallback.

## Transport and ownership

The candidate client negotiates `durable-session-v1` on a new physical WebSocket,
with automatic reconnect disabled. Password joins use the existing server policy
authentication. Join/resume/transfer intents commit to IndexedDB before emission;
grants commit before the bounded publication cut. Resume keeps the original
session; uncertain resume uses one explicit original-CAS transfer. A lost initial
join or transfer cannot fall back to password join or invent credentials.

Only a validated cut, durable ACK confirmation and live publication reconciliation
allow sending. All server handlers share the existing physical owner used by
text, image, DM and upload authorization. Credential publication permanently
fences legacy upload authority. There is no new general public resume capability.

The private page exposes text only. It does not migrate public pending operations,
files, images or DMs. Original private session ID is part of its durable outbox
and draft scope. One UNKNOWN is reserved before dispatch, retained on every
uncertain failure, and never resent or rebound. Newer draft revisions survive
confirmation cleanup. Tab-local scope is not clone isolation or an authentication
boundary. Storage eviction/power loss is not guaranteed.

## Read-only resolution

`private-text-receipt` uses `ResumeTextReceiptReader`, never `saveOnce`.
The original session, room, key, type, canonical payload hash and persisted
message identity/content must match. The transactional gate revalidates current
generation, physical transport, policy and expiry. SELECT/locking only; no
message/receipt INSERT, update, deletion or expiry extension. Missing, expired,
denied, conflicting or deleted receipts remain UNKNOWN. The handoff checks
current physical membership again. No history-derived confirmation.

## Reproduction

After dependencies and production build:

```sh
PATH=/opt/homebrew/opt/node@24/bin:$PATH SSL_CERT_FILE=/etc/ssl/cert.pem \
PG_BIN=/path/to/postgres/bin QA_CHROMIUM_PATH=/path/to/chrome \
python3 scripts/qa-public-session-fixture.py --private-browser
```

Uses a new loopback-only PostgreSQL cluster with disposable fixture data and
three distinct pool objects; this is NOT managed role/TLS isolation proof.
Actual server, rendered Chrome, real IndexedDB and WebSocket interception:
authenticated join and empty cut, drop message ACK after SQL commit, reload,
same session/new generation, retain UNKNOWN and newer draft, read-only settlement,
exactly one original message and one wire send; IndexedDB abort before join;
same-room/password/name but different session cannot resolve the original key.

Unit tests additionally cover absent/deleted/corrupt receipts, wrong owner/type/
payload, copied binding, DB policy denial, detach and read transaction failure;
actual socket negotiation, cut/ACK identity, retained confirmation retry, poll
identity, overlap, stale handoff and lifecycle drain.

## Remaining release gates

Managed NEW-image acceptance and independent DB preservation are still required.
The earlier 3.0.33 image must not be restarted as this proof. Public all-media
migration, sustained admission/expiry, physical provider capacity, paired old-
writer-fenced recovery and exact release audit remain separate requirements.
