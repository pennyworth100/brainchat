# Dimle 3.0.7 — downloadable dotted attachment names

Fixes #14: uploading a file such as report..txt succeeded and created a
message, but its download returned HTTP 403. The upload download guard now
rejects whole parent-directory segments instead of every consecutive-dot substring.
Existing accepted files with ordinary names containing consecutive dots can
be downloaded without re-uploading.

Raw and percent-encoded parent segments (including encoded separators)
remain blocked. Malformed percent encoding remains HTTP 400. Static-root
confinement, dotfile handling, attachment/same-origin headers, upload
authentication, and storage format are unchanged.

No database changes or dependency changes. Integration coverage exercises
three dotted names, persisted-history uniqueness, download bytes and headers,
and six raw-path rejection cases. This is a local/server regression proof,
not physical iPhone or staging listener acceptance.

Production deployment still requires fresh explicit Max approval. Listener
restart, new candy986 test messages and physical BRA-11 remain on HOLD.
