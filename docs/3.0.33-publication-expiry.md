# Private publication expiry and admission (3.0.33)

The existing `ResumeStore.cleanupExpired` can recover the private publication
subscriber limit without deleting messages, the global journal, or live ACK and
idempotency receipts. This is **not a deployed scheduler or a bounded database**.
No new migration, runtime handler, version or public capability is registered.

## Executable evidence

`qa-publication-runtime-role.ts`, included in the owned PostgreSQL 16/18 fixture,
fills all 100 subscriber slots. An actual new session's snapshot fails closed at
capacity. Expiring only a subscriber row does not authorize deletion of its
still-live parent session, and does not make capacity available.

After two parent sessions expire, cleanup runs through a separate authenticated
non-superuser LOGIN using the existing bounded SQL, not an administrator SET
ROLE. One parent is held `FOR UPDATE` by another connection. With a two-second
statement timeout, `cleanupExpired(1)` skips it, deletes the other, and returns
zero on the next call. A new snapshot immediately reuses the recovered slot.
After releasing the lock, the next bounded call removes the remaining expired
parent. Cascades remove its subscriber, delivery, snapshot and write receipts.

The original live session retains both its settled ACK set and keyed write
retry result: reconciliation is empty and retry returns the same message ID,
not a duplicate. Both messages and both global publication entries survive.
Cleanup returns zero when only live parents remain. Runtime cleanup is denied;
the maintenance login cannot directly delete messages, journal or delivery rows,
change session expiry, or truncate sessions. No live service is touched.

## Authority and limits

Parent expiry is the authority. Subscriber expiry alone, ACK, emit, a missing
socket, elapsed delivery lease or browser disconnect is not deletion authority.
Do not delete a live subscriber to accommodate a new one: that discards its ACK
provenance and can replay old messages. Session expiry is not refreshed by the
existing resume lookup/CAS protocol.

The maintenance role in this fixture is a **trusted maintenance principal**:
its DELETE grant can target live sessions if different SQL is supplied. The
expiry restriction is enforced by the tested helper, not an RLS/security-definer
capability. Do not present these grants as a complete production policy. The
runtime lacks DELETE; real credentials, function/default/PUBLIC grants and
deployed pools remain part of release audit.

The batch bounds parent rows, not scan time, cascading receipt count, WAL,
physical allocation or work while waiting for child locks. SKIP LOCKED proves
the held parent case only. Busy expired parents can defer capacity recovery;
admission must continue to fail closed. No scheduler is added by this proof.

## Remaining critical path

Subscriber capacity is reclaimable after real parent expiry, but message and
global-journal growth is still unbounded. Live publication receipts still cap
at 256 and fail closed, rather than silently prune ACKs. A sustainable design
must bound write admission, receipt/cascade work and maintenance cadence while
preserving supported retry windows. Message deletion/retention cannot be wired
concurrently until the append-only/fencing or versioned tombstone contract is
implemented. Physical byte/inode capacity, deployed pool authority, public
rendered resume/reload and fresh fenced paired recovery remain separate gates.
