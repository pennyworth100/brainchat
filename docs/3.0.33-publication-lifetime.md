# Private publication reconciliation lifetime

`startPublication` requires the exact physical connection, request ticket and a
confirmed full/empty cut. It installs one owned polling lifetime before network
effects. The controller stays SYNCING until its first successful reconciliation,
then allows private READY operations and continuing journal batches.

READY is the conjunction of a confirmed cut and a live continuing reconciliation
owner. A successful empty poll is NOT evidence that concurrent writers drained,
nor does READY promise exactly-once delivery, rendered UI or reload durability.
The callback is a trusted private adapter, not an untrusted wire declaration.

One poll at a time, one second cadence after settlement, four second flight
deadline, and lease expiry bound the lifetime. False, rejection, synchronous
failure, deadline or expiry cancels it and blocks operation authority. No blind
automatic retry after failure. Disconnect or explicit join aborts the signal and
cancels timers; late results cannot promote a successor. The underlying SQL may
remain unsettled: abort does not release its existing server admission slot or
claim rollback. A new physical resume requires a new confirmed cut/lifetime.

An operation-time liveness check also fences an event-loop suspension before
timers run. Pending operation objects/keys survive same-owner disconnect/resume;
journal projection never settles them. Explicit logical rejoin remains the sole
destructive owner change, and the caller must retain unresolved payloads.

Evidence: deterministic deadline/expiry/overlap/cancel/failure regressions;
controller stale-physical/request, malformed READY batch, resumed-generation and
pending-key checks; owned PostgreSQL and Socket.IO prove full AND empty cut,
actual first poll, later commit after READY and disconnect revocation. Existing
lost-confirmation/lost-batch-ACK and lower-ID late-commit tests remain.

This is still a PRIVATE 3.0.33 draft, not public handler activation. Authenticated
rendered text/image/file recovery, actual file bytes, all actual producers,
reload/payload policy, migration/roles/tombstones, bounded retention/admission,
provider physical capacity and release recovery/audit gates remain open.
