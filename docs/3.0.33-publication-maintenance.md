# Private bounded publication maintenance (3.0.33)

This completes one maintenance primitive for draft PR #44. It is not a startup
migration, deployed scheduler, retention feature, physical quota or release PASS.
The existing unpublished 3.0.33 version is retained.

## Contract

`new ResumeSessionCleanup(maintenancePool, true)` opts into the private publication
schema. Without this option, the existing non-publication schema behavior remains.
Before activation the actual deployed pool/role and schema must be integrated;
do not use the legacy parent-only `ResumeStore.cleanupExpired` with a delivery backlog.

One transaction selects at most one truly expired session, using database time and
`FOR UPDATE SKIP LOCKED`. It also locks its subscriber row: delivery FK insertion
references that row, not the session. This fences both retry and delivery child
insertion before the final empty checks. Statements use the existing 500ms server
statement timeout and 100ms lock timeout. Connection acquisition or transport loss
is not falsely declared settled by a JavaScript timeout.

Across retry receipts and delivery rows, at most **100 rows total** are deleted
per pass. The session remains until both backlogs are empty. Only then can at most
one subscriber and one snapshot-attempt row cascade with the one parent deletion.
The snapshot array is separately bounded by the private schema (256 message IDs).
Global messages and the publication journal are untouched. No live session ACK or
retry receipt is pruned, and the monotone message-write budget is not refunded.

The separate maintenance LOGIN needs SELECT/DELETE and column UPDATE for row locks
on the two child tables, plus SELECT/UPDATE(session_id) on subscribers, in addition
to its existing session grants. It remains a trusted maintenance role, not expiry
RLS: arbitrary SQL with its DELETE authority can bypass the helper. Runtime must
not inherit those grants, and neither role may own the tables.

`ResumeSessionScheduler` accepts this primitive unchanged in cadence: one pass,
then a nominal 1-second timer **after actual settlement**, bounded exponential
failure backoff to 60 seconds, no eager drain or overlapping transactions. Its
report includes delivery counts only when the publication option supplies them.
Stop retains the in-flight transaction until COMMIT/ROLLBACK and pool release.
No production scheduler was activated by this change.

## Acceptance

The disposable PostgreSQL fixture uses separate real runtime/maintenance LOGINs.
An expired subscriber has 205 delivery ACK rows, three retry receipts and one
snapshot row. An actual held child-row lock forces SQL lock timeout: all receipt
deletes roll back. Subsequent passes delete 3+97, then 0+100; the existing real
timer scheduler removes the final eight and the now-empty parent. Live ACK and
same-key retry are preserved, as are all 207 messages and journal records.

Row counts are not CPU/I/O, index scan, WAL, disk or inode bounds. More expired
sessions than the cadence can drain may accumulate; admission and capacity policy
must account for that. This work does not resolve the provider physical BYTE+INODE
contract, public producer error handling, deployed grants, rendered resume/reload,
file-byte proof, fresh OLD-writer-fenced paired backup or exact NEW-image audit.
