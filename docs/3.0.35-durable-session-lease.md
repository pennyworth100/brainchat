# 3.0.35 — private durable session authority journal

This patch is a prerequisite, NOT public resume enablement. No server event, UI
transport, upload fallback, existing outbox or production behavior is changed.

The journal records initial join intent before transport, then stores the
authenticated original lease before any future READY/dispatch. Reload preserves
the original token, session, absolute expiry and exact in-flight CAS provenance.
An interrupted initial join cannot invent a token. A pending resume cannot be
blindly repeated: only a single explicit transfer of the original CAS is allowed.
Lost transfer acknowledgement is terminal in this primitive. Storage completion
is not network delivery, server authentication, synchronization or READY.

Strict IndexedDB transactions serialize compare-and-swap by random revision.
Concurrent/stale writes abort. Input is cloned before asynchronous access. Eight
owner records maximum, no eviction/deletion or expiry extension. Expired records
remain readable for diagnosis and retention, but cannot authorize mutations.
Bearers must never enter logs, telemetry, URLs or room broadcasts. Same-origin
script access and cloned tabs are not isolated by a local scope string.

Still required before public activation:
- Compose this journal with authenticated negotiated join/resume and the private
  controller; full synchronization and current physical transport fencing.
- Bind every pending text/image/file/DM producer to original server authority.
- Authenticate a read-only original-owner exact-key/type/payload receipt lookup;
  missing/denied/deleted/expired remains UNKNOWN, never unsent or replayable.
- Preserve strict upload storage authority without legacy fallback.
- Managed new-image reload/lost-ACK/wrong-owner/storage-failure acceptance and
  independent room/database preservation; then recovery and release gates.

Existing credential-less UNKNOWN outbox entries cannot be retroactively assigned
to these leases. They remain retained without replay or inferred settlement.
