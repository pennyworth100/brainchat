## Historical foundation increments

Private request accounting now supports an awaited parser-finalization hook
after exact EOF, sharing the original absolute deadline and settlement rules.
It does not install a multipart dependency or activate a route; parser callbacks
alone never authorize storage finalization, DB dispatch, publication or refunds.

Private DB inventory adds attempt-local session-room comparison in the pinned
snapshot, with explicit missing/deleted/oversized unknowns and concurrent-update
regressions. Ledger arithmetic, receipt facts and authorization remain separate.

Private DB inventory now compares receipt-local session room/username and
canonical file payload hash in its pinned read-only snapshot. Bounded unknowns
remain explicit; no names/tokens are reported, no full identity or repair claim,
and no public activation. See ../resume-upload-reconciliation.md.

Private text adapter now composes committed retry receipts with exact owner and
membership checks, immutable request-local ACK and individually fenced fanout.
Existing receipts never replay fanout; partial outbound failures remain explicit
committed outcomes (see ../resume-text-send.md). Public handlers remain OFF.
Text sends now cap unresolved work per physical socket and process (default 100),
retaining leases across owner loss until actual settlement and handoff completion.
Concurrency rejection is pre-dispatch only. Text deadlines now return explicit
uncertain outcomes, suppress late ACK/fanout and observe late errors while holding
leases until actual settlement; rate policy remains open. No automatic retries.

Private guarded sync/probe adapter now rechecks exact physical owner/membership
before reads and ACK, recomputes presence, and caps outstanding reads per socket
(see ../resume-sync.md). No public-handler wiring or atomic snapshot/delta claim.
Full sync now shares aggregate capacity and a monotonic deadline, retaining
capacity until actual settlement after timeout/close; late errors cannot cause
late ACK, unhandled rejection or automatic retry.

Private admission/membership lifecycle and exact outbound send/broadcast fencing
are implemented (see ../resume-lifecycle.md and ../resume-outbound.md). They remain
unused by public handlers. Ordinary join/presence and all broadcast paths must be
migrated coherently before enabling resume. Earlier foundation-only open items
below are not a current completion checklist; follow the PR checkpoints.

Private history reads now use the operation gate's dedicated transaction and
current DB policy/generation checks (see ../resume-authorized-history.md).
Newest-100 same-room history is released only after successful COMMIT; denial
returns no rows. Public handlers and atomic snapshot/delta reconciliation remain
unimplemented; this does not change deployment or acceptance status.

Adds an unused server-only PostgreSQL store and additive schema. A trusted
authenticated join may issue a random 32-byte token, storing only its hash.
Lookup checks room, token, session, DB-clock absolute 24h TTL, revocation and
room auth version. Reads do not renew TTL. DB failures propagate, never grant
membership. Generation-scoped revocation cannot revoke a newer generation.

No socket endpoint calls this module. No token is issued to real clients.
Remaining before integration: CAS winner and ACK idempotency/recovery, protected
operation generation guards, transactional password-version bump, rate limits,
bounded cleanup, sessionStorage/UI and snapshot/gap semantics; full rev1 contract
acceptance matrix and physical QA. Do not merge this draft as complete resume.

Migration adds rooms.auth_version and room_resume_sessions. Production migration
lock budget, backup/restore and explicit production approval remain required.

### Ownership and ACL fidelity: separate from data/schema fidelity

The three earlier native database, paired-file and FK restore probes used
`--no-owner --no-privileges`. Their row/schema results remain valid, but those
flags deliberately omit ownership and privilege restoration; they are not
evidence that the restored application can operate under its intended roles.

The [isolated ownership/ACL proof: 7/7 assertion groups](https://github.com/pennyworth100/brainchat/issues/18#issuecomment-6098573379)
pins draft `3baa438e43f9ccb26a5755076f7d26cb94394961`, with all ten migrations
and native PostgreSQL 18.4 server/dump/restore clients. Run time was
`2026-10-10T14:32:12.740Z` through `2026-10-10T14:32:13.774Z`.
Restoring the custom-format archive **without** either stripping flag preserved
the exact owners and sorted ACL entries for 2 schemas, 29 objects and 2
default-privilege records. Fresh non-superuser application connections verified
their effective/session identity and successful SELECT/INSERT/sequence use;
UPDATE, DELETE, schema DDL, journal read, owner-role escalation and outsider
read were denied before and after restore. Newly owner-created tables and serial
sequences exercised default privileges in both databases. All 15 expected
denials matched SQLSTATE `42501`.

The negative control restored the **same archive** with both stripping flags:
objects became owned by the restoring `qa` role, default-privilege records were
absent and the application role could not SELECT. This is a controlled
permission-loss result, not an observed production outage or advice to change
live grants.

**Prerequisite and boundary:** the synthetic owner, application and outsider
roles were pre-provisioned in the same disposable cluster. This is neither the
actual production policy nor a least-privilege recommendation. It does not prove
global role/password/membership restoration, database-level ACL recovery or
that a managed-service restore principal has the required authority. Live
effective grants, RLS, column ACLs, SECURITY DEFINER functions, extension
ownership and cross-version restore remain unverified. No paired files,
backup provenance/retention, writer barrier, RTO/RPO or physical quota authority
is established by this slice. The fixture archive was deleted during cleanup;
its retained digest is not a durable backup. The linked report includes the
complete harness, retained results/catalogs and SHA-256 values. No replay,
refund, reset or production authority follows from this result.
