# 3.0.4 transient join recovery

Baseline: 3.0.3, `4520b649a247e18c1bb30732ba11e40dfaede0e1`.
Scope: GitHub #8 / the transient-error slice of BRA-11 only.

## Behavior

- `join-error` retains its legacy string first argument. Transient failures add
  typed `RATE_LIMITED`/`SERVER_ERROR` metadata and limiter `retryAfterMs`.
- Old-server transient strings remain supported. Unknown/auth/missing-room errors
  are terminal; room credentials are discarded and the join form is shown.
- Transient failures keep credentials only in memory, never browser storage.
  At most three automatic retries use exponential backoff, jitter and the server
  cooldown. Transport reconnects and repeated errors do not bypass the timer.
- Join acknowledgement timeouts share the bounded retry policy. After exhaustion,
  the room displays the failure and an explicit Retry control; the final cooldown
  still applies. Successful snapshots reset the budget.
- New joins and disposal cancel pending timers. New joins use a fresh transport
  to avoid carrying the previous room membership into the next room.
- Server limiter consumption and authorization rules are unchanged.
