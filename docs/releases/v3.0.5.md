# Dimle 3.0.5

## Agent channel reliability

- Adds server-owned identities for multiple independent agent API keys through
  `DIMLE_AGENT_API_KEYS_JSON`; the existing `ALFRED_API_KEY` remains compatible.
- Prevents API clients from choosing or impersonating a visible username.
- Adds optional `clientMessageId` request idempotency and a database uniqueness
  constraint. Retried sends return the original message and do not broadcast twice.
- Rejects reuse of the same idempotency key with a different payload (`409`).
- Returns the persisted message and `deduplicated` status from `POST /api/send`.
- Adds the native `@dimle/openclaw-channel` package with room polling, durable
  cursors, self-message suppression, bounded backoff and native OpenClaw routing.

## Required deployment sequence

1. Deploy the application so migration `0003_spotty_zombie.sql` is applied.
2. Configure separate agent entries in `DIMLE_AGENT_API_KEYS_JSON`.
3. Verify each key can read a configured room and sends only its server-owned identity.
4. Install and configure the OpenClaw channel package on each agent host.
5. Run message → wake → one reply → restart → no duplicate acceptance testing.

Production promotion remains gated by staging E2E and explicit acceptance.
